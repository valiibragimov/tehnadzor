# Участие в проекте

В issue или pull request опишите проблему и затронутый сценарий. Делайте изменения сфокусированными и объясняйте, как вы их проверили. Исправления документации приветствуются; изменения приложения требуют проверки соответствующего сценария строительного контроля.

Настройка и команды тестирования описаны в [руководстве по разработке](docs/development.ru.md), границы модулей — в [архитектуре](ARCHITECTURE.ru.md). Инженерные правила репозитория находятся в [AGENTS.md](AGENTS.md).

## Перед отправкой изменений

- Сохраняйте единицы измерения, допуски, нормативные ссылки и идентификаторы сохранённых записей.
- Отделяйте расчёты от UI и хранения. Используйте существующие публичные API модулей и общие контракты.
- Добавляйте тесты для изменённого поведения, особенно расчётов, преобразования IFC, отчётов, конкурентного доступа и форматов данных.
- Выполняйте проверки из [README](README.ru.md#разработка-и-тесты). Для изменений только в документации проверьте команды и ссылки; если меняется поведение приложения, нужны тесты.
- Объясняйте изменения схемы, порядок миграции и восстановления. Не запускайте миграции на реальных данных при разработке.

После изменения HTTP-контракта выполняйте `npm run api:generate`. После изменения общих деклараций публикации BIM выполняйте `npm run shared:generate`. Включайте сгенерированные контракты в коммит вместе с исходниками.

Не редактируйте результаты сборки вручную: `dist/`, `dist-demo/`, `dist-hosting/`, `server/dist/`, `functions/dist/`, корневые `index.html` и `sw.js`.

Используйте синтетические тестовые данные. Не включайте учётные данные, локальные файлы окружения, закрытые модели, персональные сведения и конфиденциальную строительную документацию в коммиты, логи или скриншоты. Порядок сообщения о чувствительных проблемах описан в [политике безопасности](SECURITY.ru.md).

## Языки документации

При изменении описанного поведения, настройки или ограничений обновляйте английскую и русскую версии вместе. В начале каждого документа есть ссылка на перевод; переходы внутри документации должны сохранять выбранный язык. Команды, ключи конфигурации и пути к исходникам должны совпадать в обеих версиях.
