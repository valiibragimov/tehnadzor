# Исходники клиента

[app.ts](app.ts) собирает рабочую область. Новое поведение размещайте в соответствующем модуле, а не расширяйте точку входа.

| Каталог | Назначение |
| --- | --- |
| `features/` | Проекты, план контроля, API журнала и модули инженерных проверок |
| `app/modules/` | Существующая координация экранов и старые реализации модулей |
| `app/services/` | Существующие прикладные и интеграционные сервисы |
| `app/repositories/` | Адаптеры хранения в Firestore |
| `app/pages/` и `app/profile/` | Точки входа статических страниц и код профиля |
| `app/ui/` и `app/pdf/` | Общие обработчики DOM и поддержка PDF |
| `app/vendor-src/` и `app/vendor/` | Исходники vendor-бандлов и декларации их контрактов |
| `infrastructure/` | Типизированный HTTP-клиент, фасады Firebase и общий адаптер публикации |
| `index-partials/` | Исходники генерируемого корневого `index.html` |
| `shared/` и `types/` | Небольшие общие клиентские модули и декларации |
| `demo/` | Изолированный режим с примерами данных и заменяющими адаптерами |

Модуль предоставляет небольшой публичный API через `index.ts`. Другие модули обращаются к нему через этот API или зависимости, переданные при сборке рабочей области. UI вызывает сервисы; репозитории отвечают за хранение. Не добавляйте глобальные связи состояния и не превращайте общие модули в склад несвязанных функций.

Старые файлы в `app/modules/` и `app/services/` относятся к переходной структуре. В новом коде соблюдайте границы модулей; переносите старую логику только вместе с тестами её реальных потребителей.

Границы компонентов описаны в [архитектуре](../../ARCHITECTURE.ru.md), сборка и браузерные тесты — в [руководстве по разработке](../../docs/development.ru.md).
