# Tehnadzor

Tehnadzor — веб-приложение для строительного контроля. Оно помогает инженерам на объекте и командам контроля качества записывать замеры, сравнивать их с проектными значениями и допусками, а затем отслеживать устранение замечаний в рамках проекта.

В основе приложения — четыре вида проверок: геодезические координаты и отметки, армирование, геометрия конструкций и прочность бетона. IFC-модели дополняют натурные измерения сведениями об элементах и доступными проектными значениями.

Проект активно развивается. Инженерные проверки опираются на российские СП и ГОСТ. Интерфейс доступен на русском и английском; часть результатов и текстов отчётов пока остаётся на русском.

## Возможности

- Создавать проекты и группировать проверки по конструкциям, этажам и осям.
- Записывать проектные и фактические значения, оценивать отклонения и возвращаться к сохранённым проверкам.
- Вести журнал замечаний и выполнять повторный контроль, сохраняя исходные результаты.
- Смотреть в плане контроля, какие проверки нужны и где ещё нет записей.
- Импортировать элементы IFC, выбирать их в инженерных формах и просматривать модель в 3D.
- Просматривать сводку и аналитику по проекту, выгружать журнал в CSV или JSON и готовить отчёты, в том числе в PDF.

Поддержка IFC неполная. Если проектный размер отсутствует или его извлечение не поддерживается, поле остаётся пустым: приложение не вычисляет его по отображаемой сетке. Поддерживаемые данные, работа с координатами и ограничения по размеру моделей описаны в [документе о BIM и IFC](docs/bim.ru.md).

## Как устроено приложение

Клиент написан на TypeScript, HTML и CSS без UI-фреймворка. Firebase Authentication отвечает за вход, Firestore — за хранение проектов и результатов проверок.

Express API предоставляет серверный импорт IFC и формирование отчётов. Общий адаптер WebIFC разбирает IFC в браузерном Worker или в ограниченном пуле Piscina на сервере. Для 3D-просмотра используются Three.js и IFC-Lite. Текст отчёта собирается из результатов проверок и не требует внешней ИИ-модели.

HTTP-контракт описан в OpenAPI. Клиент использует сгенерированные типы и идентификаторы маршрутов через `openapi-fetch`. Переводы интерфейса хранятся в i18next. Отдельная Firebase Function обслуживает новостную ленту профиля.

Границы модулей и согласованность данных описаны в [архитектуре](ARCHITECTURE.ru.md).

## Локальный запуск

Нужны Node.js версии 22.12 или новее в ветке Node 22, npm и Python 3 для статического сервера из примера. Версия Node указана в [.nvmrc](.nvmrc).

```sh
git clone https://github.com/valiibragimov/tehnadzor.git
cd tehnadzor
npm ci
npm ci --prefix server
npm ci --prefix functions
```

Скопируйте [.env.example](.env.example) в `.env` и заполните все шесть значений `FIREBASE_WEB_*` из **тестового проекта для разработки** в Firebase. Настройте Authentication и Firestore в этом проекте: сборка клиента сама по себе не настраивает эти сервисы.

```sh
npm run build:client
python -m http.server 8000 --bind 127.0.0.1
```

Откройте <http://127.0.0.1:8000/>. После изменений исходников пересобирайте клиент.

Чтобы посмотреть рабочую область без Firebase, воспользуйтесь [изолированным демо](docs/development.ru.md#изолированное-демо). Оно работает с локальными примерами данных и поддерживает импорт метаданных IFC. Графики заменены заглушками, экспорт PDF и просмотр модели отключены.

Настройка Firebase, необязательного API, сборка и требования к тестам описаны в [руководстве по разработке](docs/development.ru.md).

## Разработка и тесты

```sh
npm run api:check
npm run shared:check
npm run typecheck
npm run lint
npm run build
npm test
npm run test:integration
npm run audit:all
```

`npm test` собирает клиент и демо, затем запускает smoke-тесты, тесты основных модулей и браузерные сценарии Playwright. В Windows браузерные тесты используют установленный Google Chrome; в Linux нужен `npx playwright install --with-deps chromium`. Интеграционным тестам Firestore требуется Java 21+. Они работают с синтетическими данными в изолированном локальном эмуляторе.

[CI](.github/workflows/ci.yml) выполняет эти проверки для pull request в `main`. Правила изменения HTTP-контрактов и общих BIM-контрактов приведены в [руководстве для участников](CONTRIBUTING.ru.md).

## Текущие ограничения

- Большие модели читаются из Firestore постранично, но объём памяти для метаданных всё ещё растёт с числом элементов. Потоковой загрузки геометрии нет.
- Поддержаны не все варианты IFC, особенно сложные размещения и геопривязка. Импортированные координаты и размеры нужно сверять с проектом.
- Серверные импорты выполняются в очереди одного процесса и привязаны к запросу. Распределённой очереди с сохранением заданий нет.
- Перевод на английский ещё не завершён. Смена языка не меняет сохранённые инженерные значения и нормативные обозначения.
